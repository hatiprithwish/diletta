## How Diletta uses it

- One bucket per env, bound as `FILES_BUCKET`: `diletta-files-staging`, `diletta-files-production` (created by hand, `docs/runbooks/knowledge.md`); local dev and tests use miniflare's local bucket (`diletta-files-local`, never remote).
- Every object has a `files` row (the registry) and lives at `fileR2Key(company public_id, file public_id)` = `t/{company}/{file}` (`packages/schemas/src/files/`). The key is derived, never stored.
- Only `providers/fileStorage.ts` touches the bucket (`put` with `httpMetadata.contentType`, `get`, `delete` in batches of ≤ 1000 keys). It never throws and logs keys and sizes, never bytes.
- Order: an object is written inside the row's transaction (before the commit) and deleted if that transaction rolls back; a deleted file's object goes after the commit. So a failure can leave an object with no row, never a row with no object.
- First user: knowledge documents (M2-5), one object per document, overwritten in place when a page changes. Chat images, eval transcripts and exports add their owner types when they land.
